What is Python? (Definition)

Definition: Python is a high-level, interpreted, general-purpose programming language. "High-level" means it reads close to plain English rather than machine code; "interpreted" means the Python interpreter reads and runs your code directly, without a separate compile step you have to trigger yourself. It was created by Guido van Rossum and first released in 1991. The name comes from the British comedy show Monty Python's Flying Circus, not the snake.

Break the definition into its parts, one by one:

  • High-level: you write print("hi") instead of managing memory addresses or CPU registers by hand.
  • Interpreted: code runs line by line through the Python interpreter (CPython is the default, official one). There is no separate "compile" step like in C/Java — you just run the file.
  • Dynamically typed: you don't declare a variable's type up front (no int x = 5;); Python figures the type out from the value at runtime.
  • General-purpose: not built for just one job — the same language is used for web apps, data analysis, automation, AI, and desktop GUIs.
  • Multi-paradigm: supports procedural (step-by-step), object-oriented (classes/objects), and functional (functions as values) programming styles.
  • Batteries included: a large standard library ships with every install, so common tasks (dates, math, files, JSON) work without installing anything extra.

Example — the same idea in Python vs. a lower-level language:

print("Hello, World!")   # Python: one readable line

# Compare: the same output in C needs a compile step and more code:
# #include <stdio.h>
# int main() { printf("Hello, World!"); return 0; }

Features of Python (Definition List)

Exam-style definition: a "feature" is a built-in characteristic of the language that explains why it behaves, and is used, the way it is. Python's key features, one by one:

  1. Easy to Learn & Read — simple English-like syntax and mandatory indentation force clean, readable code.
  2. Interpreted Language — executes line-by-line, so errors are reported as they're reached and there's no separate compile step for the programmer.
  3. Dynamically Typed — a variable's type is decided at runtime and can even change (x = 5 then later x = "five" is legal).
  4. Object-Oriented — everything is an object; supports classes, inheritance, polymorphism, encapsulation.
  5. Free and Open Source — free to download, use, and even modify; source code is publicly maintained.
  6. Portable / Platform Independent — the same .py file runs on Windows, macOS, and Linux without changes (the interpreter handles the differences).
  7. Extensive Standard Library — built-in modules for math, files, dates, networking, JSON, and more (the "batteries included" philosophy).
  8. Large Ecosystem of Third-Party Libraries — Flask/Django (web), NumPy/Pandas (data), TensorFlow/PyTorch (AI), installed via pip.
  9. Extensible & Embeddable — you can call C/C++ code from Python and embed Python inside other applications.
  10. Automatic Memory Management — Python's garbage collector frees unused memory for you; no manual malloc/free.

Example proving "Dynamically Typed" and "Automatic Memory Management":

python-features.py
x = 5
print(type(x))     # <class 'int'>

x = "five"          # same variable, new type - allowed, no error
print(type(x))     # <class 'str'>

# no manual memory management needed - Python cleans up automatically
y = [1, 2, 3]
del y               # marks it for garbage collection, done for you

Advantages & Disadvantages of Python (Exam Points)

A very common exam question. Learn it as two clean lists with a one-line reason for each.

Advantages:

  1. Easy to learn and use — simple syntax, close to English, good for beginners.
  2. Readable & maintainable — mandatory indentation keeps code blocks visually clear.
  3. Large standard library + third-party packages — less code to write from scratch.
  4. Cross-platform / portable — write once, run on Windows/Mac/Linux.
  5. Great for rapid prototyping — interpreted, no compile wait, fast to test ideas.
  6. Strong community support — huge community means lots of tutorials, forums (Stack Overflow), and ready-made libraries.
  7. Versatile — one language for web, data science, automation, scripting, AI, and GUIs.

Disadvantages:

  1. Slower execution speed — being interpreted, it's generally slower than compiled languages like C++ or Java.
  2. High memory consumption — Python's flexibility (dynamic typing, objects for everything) uses more memory than lower-level languages.
  3. Global Interpreter Lock (GIL) — in CPython, only one thread executes Python bytecode at a time, limiting true CPU-bound multi-threading (multiprocessing is used instead).
  4. Not ideal for mobile app development — weaker mobile-app tooling compared to Kotlin/Swift.
  5. Runtime errors — since types aren't checked until the code runs, some type-related bugs only appear when that line actually executes, not before.

Example illustrating a runtime type error (disadvantage #5):

def add(a, b):
    return a + b

print(add(2, 3))          # works fine: 5
print(add(2, "3"))        # error only shows up NOW, when this line actually runs
// output will appear here after you press Run

Installing Python (Step by Step)

Definition: "Installing Python" means putting the Python interpreter (the program that reads and runs your .py files) and pip (the package installer) onto your computer, and making them reachable from any terminal window via the system PATH.

Step-by-step, for each operating system:

  1. Windows / macOS: go to python.org/downloads, download the installer for the latest version, and run it.
    • On Windows, tick the checkbox "Add Python to PATH" on the first screen — skipping this is the #1 reason python "isn't recognised" later.
    • Click Install Now, then Close once it finishes.
  2. Linux (Debian/Ubuntu): most distros already include Python 3, but you can install/upgrade it and pip with your package manager (see command below).
  3. macOS (alternative): if you use Homebrew, brew install python3 is a quicker path than the installer.
  4. Verify it worked: open a terminal (Command Prompt / Terminal) and run the version-check commands below. If a version number prints back, installation succeeded.
install-python.py
# Windows / Mac -> download from python.org and run the installer
# tick "Add Python to PATH" during Windows install

# Debian / Ubuntu
sudo apt update && sudo apt install python3 python3-pip

# macOS (Homebrew)
brew install python3

# verify the install on any OS:
python3 --version
pip3 --version
ⓘ Run this in your terminal, not in the browser.

Ways to Run Python Code (Explained)

Definition: "running" Python code means handing a set of instructions to the Python interpreter, which executes them top to bottom and shows any output. There are four common ways to do this — know all four, since exams often ask you to compare them:

  1. Interactive shell (REPL — Read-Eval-Print Loop): type python3 in a terminal to get a >>> prompt, then type one statement at a time and see its result immediately. Best for quick experiments; nothing is saved.
  2. Script file: save your code in a file ending .py (e.g. hello.py), then run the whole file at once with python3 hello.py from a terminal. Best for real programs you want to keep and re-run.
  3. IDEs / code editors: tools like VS Code, PyCharm, Jupyter Notebook or IDLE give you syntax highlighting, a Run button, and a debugger built around the same two methods above.
  4. Right here, in this page: every runnable code block below has its own Run button, which executes real Python inside your browser (no install needed) and prints the output to the black panel underneath. Press Clear to wipe that panel and run again.

A variable is a name bound to a value. Python variables need no type declaration — the type is inferred at runtime, and can even change.

Naming Rules & Conventions

  • Must start with a letter or underscore, not a digit.
  • Can contain letters, digits, underscores — case sensitive.
  • Convention: snake_case for variables/functions, PascalCase for classes, UPPER_CASE for constants.
  • Avoid Python keywords (if, class, for ...) as names.
naming-rules.py
student_name = "Sanjay"      # snake_case
MAX_MARKS = 100               # constant
class Student: pass           # PascalCase class name
print(student_name, MAX_MARKS)
// output will appear here after you press Run

Operators (Full Definitions + Examples)

Definition: an operator is a special symbol that performs an operation on one or more values (called operands) and produces a result. Example: in 5 + 3, + is the operator, 5 and 3 are the operands, result is 8. Python groups operators into seven categories — go through each one by one:

CategoryOperatorsWhat it does
Arithmetic+ - * / // % ** Basic maths: add, subtract, multiply, divide, floor-divide, remainder (modulus), power
Comparison / Relational== != > < >= <= Compares two values, always returns True or False
Logicaland or not Combines boolean expressions
Assignment= += -= *= /= //= %= **= Stores a value in a variable, optionally combined with an operation
Bitwise& | ^ ~ << >> Works on the individual binary bits of integers
Identityis, is not Checks if two variables point to the same object in memory (not just equal value)
Membershipin, not in Checks if a value exists inside a sequence (string/list/tuple/set/dict)

Key exam distinction: == checks if values are equal; is checks if both names refer to the exact same object in memory. Two different lists can be equal in value but not identical in memory:

operators.py
a, b = 7, 2
print("Arithmetic:", a+b, a-b, a*b, a/b, a//b, a%b, a**b)
print("Comparison:", a > b, a == b, a != b)
print("Logical:", True and False, True or False, not True)
print("Bitwise:", a & b, a | b, a ^ b, a << 1, a >> 1)
print("Membership:", 5 in [1,2,5], "x" not in "abc")

# Identity vs equality:
list1 = [1, 2, 3]
list2 = [1, 2, 3]      # same values, different object
list3 = list1          # same object, just a second name for it
print("list1 == list2:", list1 == list2)  # True  - equal values
print("list1 is list2:", list1 is list2)  # False - different objects
print("list1 is list3:", list1 is list3)  # True  - literally the same object
// output will appear here after you press Run

match-case (Python 3.10+)

Structural pattern matching, Python's version of a switch statement.

def check(day):
    match day:

        case "Sat" | "Sun":

        case _:
            return "Invalid day"

Classes & Objects (OOP Foundations)

Object-Oriented Programming (OOP) is a programming style built around "objects" — bundles of data (attributes) and behaviour (methods) that model real-world things.

Definitions, one by one:

  • Class: a blueprint or template that defines what attributes and methods its objects will have. It does not itself hold real data — think of it as the architect's drawing of a house, not a house you can live in.
  • Object (a.k.a. Instance): a concrete thing created from a class, with its own real data. Many objects can be built from one class, just like many actual houses can be built from one drawing.
  • __init__ (constructor): a special method that runs automatically when an object is created, used to set up its initial attribute values.
  • self: refers to "this particular object" inside a method — it's how a method reaches the data that belongs to the object it was called on.
  • Attribute: a variable that belongs to an object (e.g. self.name).
  • Method: a function defined inside a class, which operates on that object's attributes.

Why use classes? They group related data and behaviour together, avoid repeating code, and model real-world entities (a Student, a BankAccount, a Car) more naturally than loose variables and functions.

class-object.py
class Student:
    def __init__(self, name, marks):   # constructor: runs when Student(...) is called
        self.name = name                # attribute
        self.marks = marks              # attribute

    def display(self):                  # method
        print(f"{self.name} scored {self.marks} marks")

# creating two separate OBJECTS from the same CLASS blueprint
s1 = Student("Sanjay", 92)
s2 = Student("Divya", 88)
s1.display()
s2.display()
print(type(s1))          # <class '__main__.Student'> - s1 is an "instance" of Student
print(s1 is s2)          # False - two separate objects, even though same class
// output will appear here after you press Run

Inheritance (Full Explanation)

Definition: Inheritance lets one class (the child / subclass) automatically reuse the attributes and methods of another class (the parent / superclass), and then add or override its own. It models an "is-a" relationship — a Dog is an Animal.

Why it matters: it avoids rewriting shared code. Instead of writing __init__ and common logic in every class separately, you write it once in the parent and every child gets it for free.

Types of inheritance in Python (know these for exams):

  1. Single: one child, one parent. class Dog(Animal):
  2. Multiple: one child inherits from more than one parent. class Child(Parent1, Parent2):
  3. Multilevel: a chain — A → B → C, where C inherits from B, which inherits from A.
  4. Hierarchical: several children inherit from the same parent (as in the example below: Dog and Cat both inherit from Animal).
  5. Hybrid: a mix of the above patterns.

Key term — super(): inside a child class, calling super().__init__(...) runs the parent's constructor, so you don't have to repeat its setup code.

inheritance.py
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return f"{self.name} makes a sound"

# Dog and Cat are CHILD classes; Animal is the PARENT class
class Dog(Animal):
    def speak(self):                       # overrides the parent's speak()
        return f"{self.name} says Woof!"

class Cat(Animal):
    def __init__(self, name, indoor=True):
        super().__init__(name)             # reuse Animal's constructor
        self.indoor = indoor
    def speak(self):
        return f"{self.name} says Meow!"

for a in [Dog("Rex"), Cat("Whiskers")]:
    print(a.speak())

print(isinstance(Dog("Rex"), Animal))   # True - a Dog IS AN Animal too
// output will appear here after you press Run

Polymorphism & Method Overriding (Full Explanation)

Definition: "Polymorphism" comes from Greek: poly (many) + morph (forms). It means the same method name can behave differently depending on which object it's called on. The caller doesn't need to know the exact class — it just calls .area() and trusts each object to know how to answer.

  • Method Overriding: a child class redefines a method that already exists in its parent class, with the same name but different behaviour (used with inheritance — see the Dog/Cat example above too).
  • Duck typing: Python doesn't check an object's exact class before calling a method — "if it walks like a duck and quacks like a duck, treat it as a duck." Any object with an .area() method works in the loop below.

Why it matters: you can write one piece of code (like the loop below) that works correctly for many different object types, as long as they share the same method name — this makes code shorter and easier to extend with new classes later.

polymorphism.py
class Shape:
    def area(self):
        return 0

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        return 3.1416 * self.r ** 2

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side ** 2

for shape in [Circle(3), Square(4)]:
    print(type(shape).__name__, "area:", shape.area())

Encapsulation (Full Explanation)

Definition: Encapsulation means bundling data (attributes) and the methods that operate on that data together inside one class, and restricting direct outside access to some of that data — forcing changes to go through controlled methods instead. Think of it like a capsule: the internal mechanism is hidden, you only interact through the exposed surface (the public methods).

Python's access-level naming convention (no true "private" keyword exists):

  • Public — self.name — accessible from anywhere, no restriction.
  • Protected — self._name (single underscore) — a convention meaning "internal use, please don't touch from outside," but Python doesn't actually block access.
  • Private — self.__name (double underscore) — Python performs name mangling, renaming it internally to _ClassName__name, which makes accidental outside access fail.

Why it matters: it protects an object's internal state from being changed in invalid ways (e.g. setting a bank balance directly to a negative number) — all changes must go through methods like deposit() that can add validation.

encapsulation.py
class BankAccount:
    def __init__(self, balance):
        self.__balance = balance   # private attribute

    def deposit(self, amount):
        self.__balance += amount

    def get_balance(self):
        return self.__balance

acc = BankAccount(1000)
acc.deposit(500)
print(acc.get_balance())
# print(acc.__balance)  # would raise AttributeError

Abstraction (Full Explanation)

Definition: Abstraction means hiding complex internal implementation details and exposing only the essential, relevant features to the user. Where encapsulation hides data, abstraction hides complexity of behaviour — you know what a method does, not how it does it internally.

Real-world analogy: driving a car, you use the steering wheel and pedals (the essential interface) without needing to understand the engine's internal combustion process (the hidden complexity).

In Python, abstraction is commonly implemented with:

  • Abstract Base Classes (ABCs) via the abc module — define method names that every subclass must implement, without providing the actual logic in the base class.
  • @abstractmethod: marks a method as required; Python refuses to create an object of a class that has unimplemented abstract methods (see the error in the example below).

Encapsulation vs. Abstraction — the classic exam confusion: Encapsulation = hiding data (using _/__). Abstraction = hiding implementation details (using abstract classes/methods) while showing only "what it does."

abstraction.py
from abc import ABC, abstractmethod

class Vehicle(ABC):
    @abstractmethod
    def start(self):
        pass

class Car(Vehicle):
    def start(self):
        return "Car engine started"

print(Car().start())
try:
    Vehicle()
except TypeError as e:
    print("Error:", e)

    return jsonify(students)

@app.route("/api/students/<int:sid>")
def get_student(sid):

class Account:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self._balance = balance

    def deposit(self, amount):
        self._balance += amount

    def withdraw(self, amount):
        if amount > self._balance:

        self._balance -= amount

    def __str__(self):
        return f"{self.owner}'s balance: {self._balance}"

def dedupe(seq):
    seen = set()
    result = []
    for item in seq:
        if item not in seen:
            seen.add(item)
            result.append(item)
    return result

Generators compute values on demand and don't store the whole sequence in memory — ideal for very large or infinite sequences.

list_version = [x*x for x in range(10000)]
gen_version = (x*x for x in range(10000))

print("list size (bytes):", sys.getsizeof(list_version))
print("generator size (bytes):", sys.getsizeof(gen_version))
print("first 5 from generator:", [next(gen_version) for _ in range(5)])
