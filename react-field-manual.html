Part 01 · Unit 01

HTML & CSS Essentials

Prerequisite

React renders to real HTML elements and is styled with real CSS — there's no shortcut around knowing both first.

What you actually need before React

  • HTML: document structure, semantic tags (header, main, section, footer), forms & input types, accessibility attributes (alt, label, aria-*).
  • CSS: the box model, Flexbox, Grid, positioning, media queries, transitions. Flexbox and Grid alone cover ~90% of component layout in React apps.
layout.css
.card {
  display: flex;
  flex-direction: column;
  gap: 12px;
  padding: 16px;
  border-radius: 8px;
}
Why it matters for React: JSX styling bugs are almost always CSS bugs wearing a React costume. Debug the box model first, the component second.

Part 02 · Unit 05

JSX

Foundations

JSX is HTML-like syntax that compiles to React.createElement() calls — it lets you describe UI using markup, inside JavaScript.

Greeting.jsx
function Greeting({ name }) {
  return (
    <h1 className="title">
      Hello, {name}! {/* JS expression inside {} */}
    </h1>
  );
}

JSX vs HTML — key differences

HTMLJSXWhy
class="btn"className="btn"class is a reserved JS word
for="id"htmlFor="id"for is a reserved JS word
onclick="fn()"onClick={fn}camelCase, function reference not string
<img><img />all tags must be explicitly closed
multiple root tags allowedone root element required (or <></>)JSX compiles to a single expression tree
Rule of thumb: {} holds a JavaScript expression (something that returns a value) — never a statement like if or a for loop directly.

Part 02 · Unit 09

State — useState

Foundations

State is data a component owns and can change. Changing it triggers a re-render.

Counter.jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(prev => prev + 1)}>
      Count: {count}
    </button>
  );
}
Never mutate state directly. Always create a new value: setUser({...user, age: 30}), setList([...list, item]) — not user.age = 30.

Part 02 · Unit 11

Lists & Keys

Foundations

Render arrays with .map(). Each item needs a stable, unique key so React can track it across re-renders.

UserList.jsx
{users.map(user => (
  <li key={user.id}>{user.name}</li>
))}
Avoid array index as key when the list can reorder, filter, or insert — React will misidentify items and can mix up state between rows.

Forms

Foundations

Forms in React are usually controlled — the input's value is driven by state, not the DOM.

ControlledUncontrolled
Value lives inReact stateThe DOM itself
Read value viavalue + onChangeref.current.value
Use whenValidating, formatting, or reacting liveSimple forms, file inputs

function LoginForm() {
  const [email, setEmail] = useState("");
  function handleSubmit(e) {
    e.preventDefault();
    login(email);
  }
  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={e => setEmail(e.target.value)} />
      <button type="submit">Log in</button>
    </form>
  );
}

Part 03 · Unit 16

Context API

Data Flow

Context shares a value with an entire subtree, without threading props through every level.

createContext()
↓
<ThemeContext.Provider value="dark">
↓
any depth: useContext(ThemeContext)
Theme.jsx
const ThemeContext = createContext("light");

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Toolbar />
    </ThemeContext.Provider>
  );
}
function Toolbar() {
  const theme = useContext(ThemeContext);
  return <div className={theme}>...</div>;
}
Watch out: every consumer re-renders when the context value changes — don't put fast-changing data in Context; reach for a state library instead.
Part 03 · Unit 17

Custom Hooks

Data Flow

A custom hook is a function starting with use that extracts reusable stateful logic out of components.

useFetch.js
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    fetch(url).then(r => r.json()).then(d => {
      if (!cancelled) { setData(d); setLoading(false); }
    });
    return () => { cancelled = true; };
  }, [url]);

  return { data, loading };
}

Part 04 · Unit 21

Authentication

Routing & Data

Auth in a React SPA typically means: log in against an API, store a token, attach it to future requests, and gate certain routes.

ProtectedRoute.jsx
function ProtectedRoute({ children }) {
  const { user } = useContext(AuthContext);
  if (!user) return <Navigate to="/login" />;
  return children;
}
Security basics: store tokens carefully (httpOnly cookies are safer than localStorage against XSS), always use HTTPS, and never hardcode secrets in frontend code.

Part 06 · Unit 26

Advanced Rendering

Quality

Suspense, Error Boundaries, and Strict Mode handle loading states, crashes, and dev-time bug detection respectively.

ErrorBoundary.jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  render() {
    if (this.state.hasError) return <h1>Something went wrong.</h1>;
    return this.props.children;
  }
}
Strict Mode double-invokes some functions in development only, to surface side-effect bugs early. It has zero effect in production.

Part 07 · Unit 31

Security

Production

Frontend security is mostly about not trusting the client and never exposing secrets.

  • Never store API secret keys, DB passwords, or private tokens in frontend code.
  • Escape/sanitize any user-generated content rendered as HTML to prevent XSS.
  • Use HTTPS everywhere; prefer httpOnly cookies for sensitive tokens over localStorage.
  • Validate input on the server too — client-side validation is UX, not security.
Part 07 · Unit 32

Accessibility

Production

Accessible React apps start with semantic HTML — ARIA is a supplement, not a replacement.

  • Use real <button>/<label> elements instead of styled <div>s where possible.
  • Manage focus explicitly after route changes or modal open/close.
  • Ensure sufficient color contrast and visible keyboard focus states.
  • Announce dynamic content changes to screen readers via aria-live.
